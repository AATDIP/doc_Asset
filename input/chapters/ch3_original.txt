3
วิธีดำเนินงาน

การพัฒนาระบบบริหารจัดการสินทรัพย์ (Asset Management) สำหรับคณะแพทยศาสตร์ โรงพยาบาลศรีนครินทร์ มหาวิทยาลัยขอนแก่น ผู้จัดทำได้รับมอบหมายให้รับผิดชอบการออกแบบและพัฒนาส่วนต่อประสานผู้ใช้ (Frontend User Interface) และระบบการโต้ตอบฝั่งไคลเอนต์ เพื่อเชื่อมโยงการทำงานร่วมกับระบบบริการหลังบ้านและฐานข้อมูล บทนี้อธิบายขั้นตอนการดำเนินงานตั้งแต่การวิเคราะห์ความต้องการ การออกแบบระบบฐานข้อมูล การออกแบบกรณีการใช้งาน การออกแบบสถาปัตยกรรมส่วนติดต่อผู้ใช้ และการพัฒนาฟังก์ชันการทำงานหลักของระบบ โดยมีหัวข้อดังนี้

3.1 การวิเคราะห์ปัญหาและความต้องการของระบบ
จากการศึกษาปัญหาและบริบทการจัดการครุภัณฑ์ของคณะแพทยศาสตร์ โรงพยาบาลศรีนครินทร์ มหาวิทยาลัยขอนแก่น พบว่าหน่วยงานมีสินทรัพย์และครุภัณฑ์ทางการแพทย์ อุปกรณ์คอมพิวเตอร์ และอุปกรณ์สำนักงานในความรับผิดชอบจำนวนมาก แต่สิทธิ์การเข้าถึงข้อมูลถูกจำกัดไว้เฉพาะบุคลากรแผนกพัสดุส่วนกลาง ทำให้เมื่อหน่วยงานอื่นต้องการตรวจสอบข้อมูล ต้องทำเรื่องขอข้อมูลผ่านแผนกพัสดุทุกครั้ง เกิดความล่าช้าและเพิ่มภาระงานซ้ำซ้อน นอกจากนี้ การโอนย้ายครุภัณฑ์ระหว่างแผนกยังขาดการบันทึกประวัติแบบรวมศูนย์ และการนำเข้าข้อมูลผ่านไฟล์ตารางทำการยังขาดระบบตรวจสอบความแตกต่างของข้อมูลก่อนบันทึกจริง ผู้จัดทำจึงกำหนดความต้องการของระบบออกเป็นสองส่วน ดังนี้
3.1.1 ความต้องการด้านการทำงาน (Functional Requirements)
1) ระบบต้องรองรับการยืนยันตัวตนและการจัดการสิทธิ์การเข้าถึงตามบทบาทผู้ใช้งาน ได้แก่ ผู้ใช้ทั่วไป ผู้ดูแลระบบ และผู้ดูแลระบบสูงสุด
2) ระบบต้องแสดงผลแดชบอร์ดสรุปยอดสินทรัพย์ ตารางแสดงข้อมูลครุภัณฑ์ที่รองรับการเลื่อนทั้งแนวตั้งและแนวนอน พร้อมระบบคัดกรองข้อมูลหลายมิติ
3) ระบบต้องรองรับการนำเข้าข้อมูลสินทรัพย์ผ่านไฟล์ Excel และระบบอัปเดตข้อมูลพร้อมแสดงผลการเปรียบเทียบความแตกต่างของข้อมูล (Data Diff Preview)
4) ระบบต้องมีหน้าต่างโต้ตอบสำหรับการโอนย้ายสินทรัพย์ระหว่างแผนกแบบกลุ่ม พร้อมกล่องค้นหาแผนกแบบพิมพ์แล้วค้นหาทันที
5) ระบบต้องสามารถสร้างรหัสคิวอาร์ (QR Code) ประจำสินทรัพย์ และจัดพิมพ์ป้ายสติกเกอร์ขนาดมาตรฐานเจ็ดสิบคูณยี่สิบสี่มิลลิเมตร
6) ระบบต้องรองรับการจัดเก็บและแสดงผลเอกสาร PDF แยกตามแผนก พร้อมหน้าต่างเปิดดูเอกสารแบบฝังในหน้าเว็บที่ปลอดภัย
7) ระบบต้องบันทึกประวัติการดำเนินงานทั้งหมดลงในบันทึกกิจกรรม (Activity Logs) แบบกลุ่มและสามารถเปิดดูรายการย่อยได้
3.1.2 ความต้องการด้านคุณภาพของระบบ (Non-Functional Requirements)
1) ด้านความมั่นคงปลอดภัย ระบบต้องมีการป้องกันการโจมตีแบบ CSRF, XSS มีการตรวจสอบชนิดไฟล์และตรวจสอบไบต์ส่วนหัวของไฟล์ PDF (%PDF-) และกำหนดนโยบายความปลอดภัยของเนื้อหา (Content Security Policy) อย่างรัดกุม
2) ด้านการตอบสนองและความพร้อมใช้งาน ส่วนต่อประสานผู้ใช้ต้องรองรับการแสดงผลแบบตอบสนอง (Responsive Design) ทั้งบนคอมพิวเตอร์และอุปกรณ์พกพา
3) ด้านประสบการณ์ผู้ใช้งาน ระบบต้องรองรับการสลับโหมดการแสดงผลทั้งแบบสว่างและแบบมืด (Light/Dark Mode) โดยไม่มีการกระพริบของหน้าจอ (Anti-FOUC) และรองรับระบบสองภาษา

3.2 การวางแผนและการทำงานของระบบ

3.3 การออกแบบระบบฐานข้อมูล
ระบบบริหารจัดการสินทรัพย์ใช้ระบบจัดการฐานข้อมูลเชิงสัมพันธ์ MySQL ผ่านไดรเวอร์ mysql2 กำหนดชุดอักขระ utf8mb4 โดยมีตารางข้อมูลหลักที่ใช้งานจริงจำนวน 7 ตาราง และตารางจัดการเซสชันที่สร้างอัตโนมัติ ดังนี้
3.3.1 ตาราง users ใช้จัดเก็บข้อมูลบัญชีผู้ใช้งานระบบ รหัสผ่านที่ผ่านการเข้ารหัสด้วย bcrypt บทบาทผู้ใช้ แผนกสังกัด และสถานะการยืนยันอีเมล ดังตารางที่ 3.1

id | INT | PK, AUTO_INCREMENT | รหัสประจำตัวผู้ใช้งาน
username | VARCHAR(50) | NOT NULL, UNIQUE | ชื่อบัญชีสำหรับเข้าสู่ระบบ
email | VARCHAR(100) | NOT NULL, UNIQUE | อีเมลสำหรับยืนยันตัวตน

role | VARCHAR(20) | DEFAULT 'user' | บทบาท (user, admin, super_admin)

3.4 การออกแบบกรณีการใช้งาน (Use Case Diagram)
ระบบแบ่งสิทธิ์การใช้งานออกเป็น 3 บทบาทหลักตามการควบคุมสิทธิ์ตามบทบาท (RBAC) ดังรูปที่ 3.6
@fig แผนภาพกรณีการใช้งานของระบบบริหารจัดการสินทรัพย์
3.4.1 บทบาทผู้ใช้งานทั่วไป (User) สามารถเข้าสู่ระบบ ตรวจสอบข้อมูลบนแดชบอร์ด ค้นหาและกรองข้อมูลสินทรัพย์ ดูรายละเอียดสินทรัพย์ ส่งออกข้อมูลเป็นไฟล์ CSV แสดงรหัสคิวอาร์ พิมพ์ป้ายกำกับสินทรัพย์ เปิดดูและดาวน์โหลดเอกสาร PDF และแก้ไขโปรไฟล์ส่วนตัว
3.4.2 บทบาทผู้ดูแลระบบ (Admin) ได้รับสิทธิ์เพิ่มเติมจากผู้ใช้งานทั่วไป ได้แก่ การนำเข้าข้อมูลสินทรัพย์ผ่านไฟล์ Excel การอัปเดตข้อมูลพร้อมตรวจสอบผลต่าง การโอนย้ายสินทรัพย์ระหว่างแผนกแบบกลุ่ม การแก้ไขและเปลี่ยนสถานะสินทรัพย์ การอัปโหลดและลบเอกสาร PDF และการเข้าถึงหน้าตรวจสอบบันทึกกิจกรรม
3.4.3 บทบาทผู้ดูแลระบบสูงสุด (Super Admin) ได้รับสิทธิ์ครอบคลุมทุกการทำงานของระบบ และได้รับสิทธิ์พิเศษเฉพาะในการจัดการบัญชีผู้ใช้ การจัดการข้อมูลแผนก การจัดการข้อมูลหมวดหมู่สินทรัพย์ และการเข้าถึงเมนูจัดการระบบทั้งหมด

ผู้จัดทำรับผิดชอบการออกแบบและพัฒนาส่วนต่อประสานผู้ใช้และตรรกะการทำงานฝั่งไคลเอนต์ทั้งหมด โดยมีรายละเอียดสถาปัตยกรรมและการออกแบบดังนี้
3.5.1 การออกแบบโครงสร้างคอมโพเนนต์ย่อย (Partials Architecture)
ผู้จัดทำจัดแบ่งโครงสร้างหน้าจอ EJS ออกเป็นส่วนประกอบย่อย ได้แก่ header.ejs สำหรับกำหนดแท็กส่วนหัวและเชื่อมต่อสไตล์ชีต navbar.ejs สำหรับแถบนำทางด้านบนและปุ่มเปลี่ยนภาษา sidebar.ejs สำหรับแถบเมนูหลักที่แสดงผลตามบทบาทผู้ใช้ และ footer.ejs สำหรับโหลดสคริปต์และตัวดักจับเหตุการณ์ส่วนกลาง การแยกส่วนประกอบช่วยให้หน้าจอทุกหน้ามีรูปแบบที่เป็นเอกภาพและง่ายต่อการบำรุงรักษา
3.5.2 การออกแบบระบบธีมสีและการป้องกันปัญหาหน้าจอกระพริบ
ผู้จัดทำใช้ตัวแปร CSS Variables ในการกำหนดคู่สีระหว่างโหมดปกติและโหมดกลางคืน และวางสคริปต์ขนาดเล็กไว้ในส่วนหัวของเอกสารเพื่ออ่านค่าธีมจากหน่วยความจำเบราว์เซอร์แล้วกำหนดคลาสบนแท็กรากทันทีก่อนการวาดหน้าจอ ช่วยแก้ปัญหาหน้าจอกระพริบได้อย่างมีประสิทธิภาพ
3.5.3 การจัดการตารางข้อมูลสินทรัพย์ขนาดใหญ่
ตารางสินทรัพย์มีจำนวนข้อมูลยี่สิบห้าคอลัมน์ ผู้จัดทำออกแบบคลาส table-scroll-wrapper เพื่อจำกัดความสูงสูงสุดให้อยู่ที่เจ็ดสิบร้อยละของความสูงหน้าจอ และเปิดให้เลื่อนได้ทั้งแนวตั้งและแนวนอน พร้อมกำหนดให้หัวตารางติดค้างอยู่ด้านบนตลอดเวลาด้วยคุณสมบัติ position: sticky ทำให้ผู้ใช้สามารถอ่านข้อมูลแถวที่มีจำนวนมากได้อย่างสะดวก

3.6 การพัฒนาโมดูลระบบและการทำงานฝั่งไคลเอนต์
ผู้จัดทำพัฒนาฟังก์ชันการทำงานส่วนต่อประสานและสคริปต์ฝั่งไคลเอนต์ในแต่ละโมดูล ดังนี้
3.6.1 แดชบอร์ดหลักและการคัดกรองข้อมูล
หน้าแดชบอร์ดประกอบด้วยการ์ดสรุปยอดสินทรัพย์ แถบค้นหาและตัวกรองสถานะ หมวดหมู่ แผนก และโรงงาน และตัวเลือกจำนวนแถวต่อหน้า โดยผู้จัดทำผูกเหตุการณ์ตรวจจับการเปลี่ยนแปลงของตัวเลือกจำนวนแถว เพื่อเซ็ตค่าหน้ากลับไปเป็นหน้าที่หนึ่งเสมอและส่งแบบฟอร์มทันที ป้องกันข้อผิดพลาดจากการแบ่งหน้า
3.6.2 การนำเข้าและเปรียบเทียบข้อมูลก่อนการปรับปรุง
หน้าอัปเดตข้อมูลทำงานร่วมกับโมดูลเปรียบเทียบข้อมูล โดยหน้าจอพรีวิวจะแยกแถวข้อมูลออกเป็นสามกลุ่ม ได้แก่ ข้อมูลที่มีการเปลี่ยนแปลง ข้อมูลใหม่ และข้อมูลเดิม โดยผู้จัดทำออกแบบตารางแสดงผลต่างให้ผู้ใช้สามารถเลือกปรับใช้ค่าใหม่หรือคงค่าเดิมได้เป็นรายคอลัมน์ พร้อมปุ่มเลือกทั้งหมดเพื่อความสะดวก
3.6.3 การโอนย้ายสินทรัพย์ระหว่างแผนกแบบกลุ่ม
ผู้จัดทำพัฒนาหน้าต่างโต้ตอบ transfer-modal.ejs และสคริปต์ dept-combo.js เพื่อเปิดใช้งานได้จากทั้งหน้าแดชบอร์ดและหน้าโอนย้าย โดยดึงชื่อแผนกต้นทางมาแสดงเป็นป้ายสถานะอัตโนมัติ และสร้างช่องค้นหาแผนกปลายทางที่รองรับการพิมพ์แล้วกรองข้อมูลทันที พร้อมรองรับการเลื่อนเลือกด้วยปุ่มลูกศรและการกดปุ่ม Enter
3.6.4 ระบบสร้างรหัสคิวอาร์และจัดพิมพ์ป้ายสติกเกอร์กำกับสินทรัพย์
ผู้จัดทำพัฒนาโมดูล qr.js ร่วมกับไลบรารี qrcode.js เพื่อเรนเดอร์ภาพคิวอาร์โค้ดลงในหน้าต่างรายละเอียด และสร้างฟังก์ชันเปิดหน้าต่างเอกสารใหม่สำหรับการจัดพิมพ์ป้ายสติกเกอร์ขนาดเจ็ดสิบคูณยี่สิบสี่มิลลิเมตร โดยใช้คำสั่งสไตล์ชีตควบคุมขนาดหน้าพิมพ์ให้สอดคล้องกับขนาดป้ายจริง
3.6.5 ระบบจัดการเอกสาร PDF และการแสดงผลที่ปลอดภัย
หน้าเอกสารรองรับการสลับมุมมองระหว่างแบบตารางและแบบการ์ด โดยบันทึกสถานะมุมมองลงในหน่วยความจำเบราว์เซอร์ และปรับปรุงหน้าต่างเปิดดูเอกสารเป็นการใช้อิลิเมนต์ iframe เพื่อให้สอดคล้องกับนโยบายความปลอดภัยของเนื้อหา (Content Security Policy) ของระบบ
3.6.6 ระบบตรวจสอบบันทึกกิจกรรมและหน้าจัดการระบบ
หน้าบันทึกกิจกรรมแสดงรายการปฏิบัติงานของผู้ใช้แบบเรียงตามเวลาล่าสุด พร้อมปุ่มเปิดดูรายละเอียดของรายการที่ทำเป็นกลุ่ม และหน้าจัดการระบบสำหรับผู้ดูแลระบบสูงสุดรองรับการจัดการบัญชีผู้ใช้ แผนก และหมวดหมู่ โดยมีระบบ SweetAlert2 ยืนยันการดำเนินงานสำคัญก่อนบันทึกจริง
