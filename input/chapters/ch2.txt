ทฤษฎีและงานวิจัยที่เกี่ยวข้อง

การพัฒนาระบบบริหารจัดการสินทรัพย์ (Asset Management) สำหรับคณะแพทยศาสตร์ โรงพยาบาลศรีนครินทร์ มหาวิทยาลัยขอนแก่น ผู้จัดทำได้รับมอบหมายให้รับผิดชอบการออกแบบและพัฒนาส่วนต่อประสานผู้ใช้ (Frontend User Interface) และระบบการโต้ตอบฝั่งไคลเอนต์ ซึ่งทำงานร่วมกับระบบบริการหลังบ้านและฐานข้อมูล เพื่อให้การดำเนินงานเป็นไปอย่างมีประสิทธิภาพและถูกต้องตามหลักวิศวกรรมซอฟต์แวร์ ผู้จัดทำจึงได้ศึกษาทฤษฎี เทคโนโลยี และงานวิจัยที่เกี่ยวข้อง โดยมีหัวข้อดังนี้

2.1 ภาษา HTML5 และโครงสร้างหน้าเว็บเชิงความหมาย
HTML5 (Hypertext Markup Language 5) คือภาษามาร์กอัปมาตรฐานสำหรับการสร้างและจัดโครงสร้างเนื้อหาของเอกสารบนเวิลด์ไวด์เว็บ มีการเพิ่มอิลิเมนต์เชิงความหมาย (Semantic Elements) เช่น ส่วนหัว ส่วนนำทาง ส่วนเนื้อหาหลัก และส่วนท้าย ซึ่งช่วยให้โปรแกรมเว็บเบราว์เซอร์เข้าใจบทบาทของแต่ละองค์ประกอบได้อย่างชัดเจน ตลอดจนรองรับการฝังวัตถุและเอกสารภายนอกผ่านกรอบหน้าต่างอินไลน์ (Inline Frame: iframe)
2.1.1 ข้อดี
2.1.1.1 โครงสร้างเชิงความหมายช่วยให้โปรแกรมอ่านหน้าจอและระบบสืบค้นเข้าใจลำดับชั้นของเนื้อหาได้ดี
2.1.1.2 รองรับการฝังไฟล์เอกสารภายนอกได้โดยตรงผ่านอิลิเมนต์มาตรฐานโดยไม่ต้องติดตั้งปลั๊กอินเสริม
2.1.2 ข้อเสีย
2.1.2.1 ทำหน้าที่เพียงกำหนดโครงสร้าง ต้องทำงานร่วมกับสไตล์ชีตและสคริปต์เพื่อให้หน้าเว็บสมบูรณ์
2.1.3 การนำไปใช้ในโครงการ
ผู้จัดทำใช้ HTML5 ร่วมกับเทมเพลตเอนจิน EJS ในการสร้างโครงสร้างหน้าจอแสดงผลทั้งหมด จัดวางตารางสินทรัพย์ หน้าต่างโต้ตอบ และใช้อิลิเมนต์ iframe สำหรับแสดงตัวอย่างเอกสารคู่มือ PDF ได้อย่างถูกต้องตามนโยบายความปลอดภัย

2.2 ภาษา CSS3 และการออกแบบตัวแปรสีระดับราก
CSS3 (Cascading Style Sheets 3) คือภาษาที่ใช้สำหรับกำหนดรูปลักษณ์และการจัดวางเลย์เอาต์ของเอกสารเว็บ รองรับการจัดวางกล่องข้อความแบบยืดหยุ่น (Flexbox) และแบบตาราง (Grid) รวมถึงมีความสามารถในการกำหนดตัวแปรสีระดับราก (CSS Custom Properties) ผ่านตัวเลือก :root ซึ่งช่วยให้สามารถบริหารจัดการชุดสีและสไตล์ของระบบได้อย่างเป็นเอกภาพ
2.2.1 ข้อดี
2.2.1.1 ตัวแปรระดับรากช่วยให้สามารถสลับธีมสีสว่างและธีมสีมืดได้ง่ายจากจุดเดียวโดยไม่ต้องเขียนโค้ดซ้ำซ้อน
2.2.1.2 การกำหนดคุณสมบัติการตรึงตำแหน่งช่วยให้หัวตารางติดค้างอยู่กับที่ขณะเลื่อนดูข้อมูลจำนวนมาก
2.2.1.3 แยกส่วนการตกแต่งออกจากโครงสร้างเนื้อหา ทำให้ปรับปรุงหน้าตาของระบบได้สะดวกรวดเร็ว
2.2.2 ข้อเสีย
2.2.2.1 คุณสมบัติการแสดงผลขั้นสูงบางประการอาจแสดงผลแตกต่างกันเล็กน้อยในเบราว์เซอร์ต่างค่าย
2.2.3 การนำไปใช้ในโครงการ
ผู้จัดทำออกแบบไฟล์สไตล์ชีตหลักกำหนดตัวแปรสีพื้นหลัง สีการ์ด และสีข้อความสำหรับโหมดปกติและโหมดกลางคืน พร้อมสร้างคลาสสำหรับเลื่อนดูตารางข้อมูลสินทรัพย์ขนาดใหญ่ได้ทั้งแนวตั้งและแนวนอนโดยที่หัวตารางยังคงตรึงอยู่กับที่

2.3 ภาษา JavaScript และการประมวลผลฝั่งไคลเอนต์
JavaScript คือภาษาโปรแกรมเชิงวัตถุที่ประมวลผลบนเว็บเบราว์เซอร์ ทำหน้าที่เพิ่มความสามารถในการโต้ตอบกับผู้ใช้งาน จัดการโครงสร้างเชิงวัตถุของเอกสาร (Document Object Model: DOM) ดักจับเหตุการณ์การกดปุ่มหรือกรอกข้อมูล และรองรับการประมวลผลแบบไม่ประสานเวลาผ่านการส่งคำขอแบบอะซิงโครนัส
2.3.1 ข้อดี
2.3.1.1 ทำงานบนเบราว์เซอร์ได้ทันทีโดยไม่ต้องติดตั้งโปรแกรมแปลภาษาเพิ่มเติมบนเครื่องผู้ใช้
2.3.1.2 ตอบสนองต่อการกระทำของผู้ใช้งานได้แบบไดนามิกโดยไม่ต้องทำการโหลดหน้าเว็บใหม่ทั้งหมด
2.3.1.3 มีฟังก์ชันและระบบนิเวศของไลบรารีเสริมที่ช่วยให้การพัฒนาส่วนติดต่อผู้ใช้มีความคล่องตัวสูง
2.3.2 ข้อเสีย
2.3.2.1 การประมวลผลขึ้นอยู่กับสมรรถนะของอุปกรณ์และเว็บเบราว์เซอร์ของผู้ใช้งานแต่ละราย
2.3.2.2 โค้ดฝั่งไคลเอนต์สามารถถูกตรวจสอบได้ จึงต้องพึ่งพาการตรวจสอบความถูกต้องฝั่งเซิร์ฟเวอร์ร่วมด้วยเสมอ
2.3.3 การนำไปใช้ในโครงการ
ผู้จัดทำพัฒนาโมดูลสคริปต์ฝั่งไคลเอนต์สำหรับควบคุมการย่อและขยายแถบเมนูด้านข้าง การสร้างระบบกล่องค้นหาเลือกแผนกแบบพิมพ์แล้วกรองข้อมูลทันที และควบคุมการทำงานของกล่องเลือกจำนวนแถวต่อหน้าบนแดชบอร์ด

2.4 บูตสแตรป (Bootstrap 5)
Bootstrap 5 คือเฟรมเวิร์กส่วนติดต่อผู้ใช้แบบโอเพนซอร์สที่ได้รับความนิยมสูง พัฒนาขึ้นด้วยแนวคิดที่มุ่งเน้นการแสดงผลบนอุปกรณ์พกพาเป็นอันดับแรก (Mobile-First) ประกอบด้วยระบบโครงร่างแบบตารางสิบสองคอลัมน์ ส่วนประกอบสำเร็จรูป และคลาสอำนวยความสะดวกในการจัดระยะห่างและสีสัน
2.4.1 ข้อดี
2.4.1.1 มีส่วนประกอบมาตรฐานพร้อมใช้งาน เช่น แถบนำทาง หน้าต่างโต้ตอบ ป้ายสถานะ และการ์ดแสดงข้อมูล
2.4.1.2 รองรับการออกแบบหน้าจอแบบตอบสนองต่อทุกขนาดอุปกรณ์อย่างมีมาตรฐานและสม่ำเสมอ
2.4.1.3 ลดเวลาในการพัฒนาส่วนต่อประสานและช่วยให้ระบบมีมาตรฐานด้านการจัดวางตำแหน่งที่สวยงาม
2.4.2 ข้อเสีย
2.4.2.1 หน้าตาของระบบอาจมีลักษณะคล้ายคลึงกับเว็บไซต์อื่นหากไม่มีการปรับแต่งสไตล์เพิ่มเติม
2.4.3 การนำไปใช้ในโครงการ
ผู้จัดทำใช้ Bootstrap รุ่น 5.3.3 ร่วมกับชุดไอคอน Bootstrap Icons ผ่านระบบ CDN ในการจัดโครงสร้างหน้าจอหลัก ออกแบบการ์ดสรุปยอดสินทรัพย์ ตารางแสดงข้อมูล ป้ายสถานะสี และหน้าต่างโต้ตอบทั้งหมด

2.5 เทมเพลตเอนจิน EJS
EJS (Embedded JavaScript Templates) คือเทมเพลตเอนจินสำหรับสภาพแวดล้อม Node.js ที่ช่วยให้นักพัฒนาสามารถเขียนโค้ดภาษา JavaScript แทรกเข้าไปในโครงสร้าง HTML เพื่อสร้างหน้าเว็บแบบพลวัตบนเครื่องแม่ข่าย รองรับการแบ่งโครงสร้างหน้าจอออกเป็นไฟล์ส่วนประกอบย่อยและนำกลับมาใช้ซ้ำ
2.5.1 ข้อดี
2.5.1.1 ใช้ไวยากรณ์ภาษา JavaScript พื้นฐาน ทำให้นักพัฒนาไม่ต้องเรียนรู้ภาษาเทมเพลตใหม่
2.5.1.2 มีแท็กมาตรฐานที่ทำการหลีกอักขระพิเศษโดยอัตโนมัติ ช่วยป้องกันช่องโหว่การฝังโค้ดอันตราย
2.5.1.3 รองรับการนำเข้าไฟล์คอมโพเนนต์ย่อย ช่วยลดความซ้ำซ้อนของโค้ดและง่ายต่อการบำรุงรักษา
2.5.2 ข้อเสีย
2.5.2.1 หากใส่ตรรกะทางธุรกิจในไฟล์เทมเพลตมากเกินไป อาจส่งผลให้โครงสร้างโค้ดอ่านยากและสับสน
2.5.3 การนำไปใช้ในโครงการ
ผู้จัดทำออกแบบโครงสร้างมุมมองทั้งหมดด้วย EJS โดยแยกเป็นส่วนประกอบย่อย ได้แก่ ส่วนหัว แถบนำทาง แถบเมนูด้านข้าง และส่วนท้าย รวมถึงสร้างหน้าแดชบอร์ด หน้าอัปโหลด และหน้าแสดงรายการเอกสาร

2.6 การเรนเดอร์ฝั่งเซิร์ฟเวอร์และการป้องกันปัญหาหน้าจอกระพริบ
การเรนเดอร์ฝั่งเซิร์ฟเวอร์ (Server-Side Rendering: SSR) คือกระบวนการที่เครื่องแม่ข่ายทำการประมวลผลข้อมูลและสร้างเอกสาร HTML สำเร็จรูปก่อนส่งไปยังเบราว์เซอร์ ซึ่งในการสลับธีมแสดงผลอาจเกิดปรากฏการณ์หน้าจอกระพริบ (Flash of Unstyled Content: FOUC) หากเบราว์เซอร์เรนเดอร์สไตล์เริ่มต้นก่อนอ่านค่าธีมจากหน่วยความจำ
2.6.1 ข้อดี
2.6.1.1 เบราว์เซอร์สามารถแสดงผลเนื้อหาหน้าจอได้ทันทีโดยไม่ต้องรอโหลดชุดสคริปต์ขนาดใหญ่
2.6.1.2 การโหลดหน้าจอครั้งแรกทำได้อย่างรวดเร็วและเป็นมิตรต่อระบบค้นหาข้อมูลของโปรแกรมค้นหา
2.6.2 ข้อเสีย
2.6.2.1 การเปลี่ยนหน้าต้องส่งคำขอและรอรับเอกสารหน้าใหม่จากเครื่องแม่ข่ายในแต่ละรอบ
2.6.3 การนำไปใช้ในโครงการ
ผู้จัดทำวางสคริปต์ตรวจสอบสถานะธีมไว้ในส่วนหัวของเอกสารก่อนการเรนเดอร์เนื้อหา เพื่ออ่านค่าธีมจากหน่วยความจำในเครื่องแล้วกำหนดคลาสบนแท็กรากทันที ช่วยป้องกันการกระพริบของหน้าจอได้อย่างสมบูรณ์

2.7 โหนดเจเอสและเอ็กซ์เพรสเฟรมเวิร์ก
Node.js คือสภาพแวดล้อมสำหรับรันภาษา JavaScript นอกเว็บเบราว์เซอร์ ทำงานบนเอนจิน V8 ด้วยสถาปัตยกรรมแบบวนรอบเหตุการณ์ที่ไม่บล็อกการทำงาน ทำงานร่วมกับ Express 5 ซึ่งเป็นเว็บแอปพลิเคชันเฟรมเวิร์กขนาดเล็กที่ใช้สถาปัตยกรรมการประมวลผลผ่านสายโซ่มิดเดิลแวร์ (Middleware Pipeline)
2.7.1 ข้อดี
2.7.1.1 รองรับการประมวลผลคำขอพร้อมกันจำนวนมากได้อย่างมีประสิทธิภาพและประหยัดทรัพยากร
2.7.1.2 ใช้ภาษา JavaScript ตลอดทั้งส่วนหน้าบ้านและส่วนหลังบ้าน ทำให้การแลกเปลี่ยนข้อมูลเป็นไปอย่างราบรื่น
2.7.1.3 มิดเดิลแวร์มีความยืดหยุ่นสูง สามารถติดตั้งระบบตรวจสอบสิทธิ์และระบบความปลอดภัยได้อย่างเป็นระบบ
2.7.2 ข้อเสีย
2.7.2.1 ไม่เหมาะสมกับการประมวลผลที่ต้องใช้พลังการคำนวณทางคณิตศาสตร์อย่างหนักบนเธรดหลักตัวเดียว
2.7.3 การนำไปใช้ในโครงการ
ระบบใช้ Node.js และ Express เป็นเครื่องแม่ข่ายหลักในการจัดการคำขอ เชื่อมต่อไปยังฐานข้อมูล กำหนดเส้นทางการเข้าถึงหน้าเว็บ และส่งข้อมูลผ่านตัวแปรไปยังเทมเพลต EJS เพื่อเรนเดอร์ส่วนติดต่อผู้ใช้

2.8 ระบบฐานข้อมูลเชิงสัมพันธ์ MySQL
MySQL คือระบบจัดการฐานข้อมูลเชิงสัมพันธ์ (Relational Database Management System) ที่จัดเก็บข้อมูลในรูปแบบตารางที่มีโครงสร้างแถวและคอลัมน์ชัดเจน มีเอนจินจัดเก็บข้อมูลแบบ InnoDB ที่รองรับคุณสมบัติ ACID และรองรับการสร้างดัชนีเพื่อเพิ่มความเร็วในการสืบค้นข้อมูล
2.8.1 ข้อดี
2.8.1.1 มีความถูกต้องสมบูรณ์และความปลอดภัยของข้อมูลสูง ป้องกันข้อผิดพลาดจากการบันทึกข้อมูลที่ไม่สมบูรณ์
2.8.1.2 รองรับการทำดัชนีบนคอลัมน์ที่ใช้งานบ่อย ช่วยให้สืบค้นข้อมูลครุภัณฑ์จำนวนมากได้อย่างรวดเร็ว
2.8.1.3 เป็นระบบฐานข้อมูลมาตรฐานที่มีเสถียรภาพสูงและเชื่อมต่อกับภาษาโปรแกรมชั้นนำได้อย่างมีประสิทธิภาพ
2.8.2 ข้อเสีย
2.8.2.1 การเปลี่ยนแปลงโครงสร้างตารางขนาดใหญ่ในระบบที่กำลังใช้งานต้องมีการวางแผนอย่างรัดกุม
2.8.3 การนำไปใช้ในโครงการ
ระบบใช้ MySQL จัดเก็บข้อมูลหลักทั้งหมด ได้แก่ ข้อมูลสินทรัพย์ ผู้ใช้งาน แผนก หมวดหมู่ ประวัติการโอนย้าย บันทึกกิจกรรมการใช้งาน และข้อมูลเอกสาร พร้อมทั้งจัดเก็บข้อมูลเซสชันของผู้ใช้ลงในตารางเฉพาะ

2.9 รหัสคิวอาร์และระบบจัดพิมพ์ป้ายสติกเกอร์กำกับสินทรัพย์
รหัสคิวอาร์ (Quick Response Code) คือสัญลักษณ์รหัสแท่งสองมิติตามมาตรฐาน ISO/IEC 18004 ที่สามารถเก็บข้อมูลตัวอักษรและตัวเลขได้จำนวนมาก สามารถสแกนอ่านข้อมูลได้อย่างรวดเร็วทุกทิศทาง ทำงานร่วมกับการจัดรูปแบบหน้าพิมพ์ด้วยคำสั่ง CSS @page เพื่อควบคุมขนาดการพิมพ์ป้ายให้ตรงกับขนาดสติกเกอร์จริง
2.9.1 ข้อดี
2.9.1.1 สามารถเก็บข้อมูลรหัสสินทรัพย์และเชื่อมโยงไปยังหน้าตรวจสอบข้อมูลได้อย่างสะดวกรวดเร็ว
2.9.1.2 มีระบบแก้ไขข้อผิดพลาดในตัว ทำให้อ่านข้อมูลได้ถูกต้องแม้พื้นผิวป้ายจะชำรุดเสียหายบางส่วน
2.9.1.3 การควบคุมขนาดผ่านสไตล์ชีตการพิมพ์ช่วยให้พิมพ์ป้ายขนาดเจ็ดสิบคูณยี่สิบสี่มิลลิเมตรได้อย่างแม่นยำ
2.9.2 ข้อเสีย
2.9.2.1 หากความละเอียดของเครื่องพิมพ์ต่ำหรือป้ายมีขนาดเล็กมาก อาจส่งผลให้อุปกรณ์สแกนอ่านได้ยาก
2.9.3 การนำไปใช้ในโครงการ
ผู้จัดทำพัฒนาโมดูลสคริปต์ร่วมกับไลบรารีสร้างคิวอาร์โค้ด และสร้างหน้าต่างเอกสารสำหรับจัดพิมพ์ป้ายสติกเกอร์ขนาดเจ็ดสิบคูณยี่สิบสี่มิลลิเมตรพร้อมข้อมูลรหัสสินทรัพย์ คำอธิบาย สัญญา และวันหมดอายุ

2.10 สถาปัตยกรรมหน้าต่างโต้ตอบและกล่องเลือกแผนกแบบไดนามิก
หน้าต่างโต้ตอบ (Modal Dialog) คือรูปแบบการนำเสนอส่วนต่อประสานที่ซ้อนทับบนหน้าจอหลักเพื่อมุ่งเน้นการดำเนินงานเฉพาะอย่าง ทำงานร่วมกับกล่องกรองข้อมูลแบบพิมพ์แล้วค้นหา (Search-as-you-type Combobox) และรองรับการนำทางผ่านแป้นพิมพ์ เพื่อเพิ่มความคล่องตัวในการทำงานของผู้ใช้
2.10.1 ข้อดี
2.10.1.1 ผู้ใช้สามารถดำเนินงานสำคัญ เช่น การโอนย้ายสินทรัพย์ ได้ทันทีโดยไม่ต้องสลับหน้าจอเว็บเพจไปมา
2.10.1.2 ช่วยให้ค้นหารายการจากตัวเลือกแผนกจำนวนมากได้อย่างรวดเร็วผ่านการพิมพ์และกดปุ่มลูกศร
2.10.2 ข้อเสีย
2.10.2.1 ต้องควบคุมการเปิดและปิดหน้าต่างให้สอดคล้องกับสถานะของระบบเพื่อป้องกันข้อมูลค้างในแบบฟอร์ม
2.10.3 การนำไปใช้ในโครงการ
ผู้จัดทำพัฒนาหน้าต่างโต้ตอบส่วนกลางสำหรับการโอนย้ายครุภัณฑ์แบบกลุ่ม โดยดึงชื่อแผนกต้นทางมาแสดงเป็นป้ายสถานะอัตโนมัติ และสร้างช่องค้นหาแผนกปลายทางที่รองรับการใช้งานผ่านแป้นพิมพ์ได้อย่างสมบูรณ์

2.11 ระบบการจัดการหลายภาษา
การจัดการหลายภาษา (Internationalization: i18n) คือกระบวนการออกแบบสถาปัตยกรรมซอฟต์แวร์ให้รองรับการแสดงผลภาษาที่หลากหลายโดยไม่ต้องแก้ไขโครงสร้างโปรแกรม โดยแยกชุดข้อความออกเป็นแฟ้มทรัพยากรภาษาในรูปแบบ JSON และส่งผ่านฟังก์ชันแปลภาษาไปยังมุมมองแสดงผล
2.11.1 ข้อดี
2.11.1.1 รองรับการเพิ่มภาษาใหม่ในอนาคตได้อย่างสะดวกเพียงเพิ่มแฟ้มข้อมูลคำศัพท์ภาษาใหม่
2.11.1.2 การสลับภาษาทำได้รวดเร็วผ่านการบันทึกสถานะภาษาที่ผู้ใช้เลือกลงในคุกกี้ของเว็บเบราว์เซอร์
2.11.2 ข้อเสีย
2.11.2.1 ผู้พัฒนาต้องดูแลและปรับปรุงรายการคำศัพท์ในแฟ้มภาษาทุกภาษาให้สอดคล้องตรงกันเสมอ
2.11.3 การนำไปใช้ในโครงการ
ระบบแยกข้อความออกเป็นแฟ้มภาษาไทยและภาษาอังกฤษ โดยผู้จัดทำเชื่อมโยงข้อความบนหน้าจอเข้ากับฟังก์ชันแปลภาษาบนเทมเพลต EJS ทั้งหมด รวมถึงสร้างปุ่มสลับภาษาบนแถบนำทางหลัก

2.12 มาตรการความปลอดภัยบนส่วนต่อประสานและเบราว์เซอร์
การรักษาความปลอดภัยของส่วนต่อประสานเว็บครอบคลุมการตั้งค่านโยบายความปลอดภัยของเนื้อหา (Content Security Policy: CSP) ผ่านมิดเดิลแวร์ Helmet เพื่อควบคุมแหล่งที่มาของสคริปต์และเฟรม การป้องกันการโจมตีแบบ Cross-Site Scripting (XSS) และการใช้หน้าต่างยืนยันการทำรายการผ่าน SweetAlert2
2.12.1 ข้อดี
2.12.1.1 ป้องกันการโจมตีและป้องกันการฝังมัลแวร์จากแหล่งภายนอกที่ไม่มีความน่าเชื่อถือได้อย่างรัดกุม
2.12.1.2 ช่วยให้การฝังไฟล์เอกสาร PDF ดำเนินการได้อย่างถูกต้องโดยไม่อนุญาตให้อ็อบเจกต์ภายนอกทำงาน
2.12.2 ข้อเสีย
2.12.2.1 การตั้งค่านโยบายที่เข้มงวดอาจปิดกั้นการทำงานขององค์ประกอบบางประเภทหากไม่ได้กำหนดข้อยกเว้นไว้
2.12.3 การนำไปใช้ในโครงการ
ผู้จัดทำปรับปรุงการแสดงผลเอกสาร PDF เป็นการใช้กรอบหน้าต่าง iframe ร่วมกับการกำหนดค่านโยบายความปลอดภัยของเนื้อหาอย่างชัดเจน และผูกระบบยืนยันการลบหรือโอนย้ายข้อมูลผ่านหน้าต่างเตือนเพื่อความปลอดภัย

2.13 เครื่องมือที่ใช้ในการพัฒนาซอฟต์แวร์
การพัฒนาส่วนต่อประสานและระบบบริหารจัดการสินทรัพย์จำเป็นต้องใช้เครื่องมือช่วยในการพัฒนาซอฟต์แวร์ที่มีประสิทธิภาพ ประกอบด้วยโปรแกรมแก้ไขซอร์สโค้ด โปรแกรมควบคุมเวอร์ชัน และเครื่องมือตรวจสอบบนเว็บเบราว์เซอร์
2.13.1 Visual Studio Code คือโปรแกรมแก้ไขซอร์สโค้ดที่รองรับส่วนขยายสำหรับการพัฒนาเว็บและการตรวจสอบไวยากรณ์
2.13.2 Git และ GitHub คือระบบควบคุมเวอร์ชันและบริการรับฝากโครงการซอฟต์แวร์ที่ช่วยบริหารจัดการประวัติการเปลี่ยนแปลงโค้ด
2.13.3 DBeaver คือเครื่องมือสำหรับเชื่อมต่อและบริหารจัดการระบบฐานข้อมูลเชิงสัมพันธ์ผ่านส่วนติดต่อผู้ใช้แบบกราฟิก
2.13.4 เครื่องมือสำหรับนักพัฒนาบนเว็บเบราว์เซอร์ คือเครื่องมือที่ฝังอยู่ในเบราว์เซอร์สำหรับตรวจสอบโครงสร้างองค์ประกอบและการทำงานของสคริปต์
2.13.5 การนำไปใช้ในโครงการ
ผู้จัดทำใช้เครื่องมือดังกล่าวในการเขียนโค้ด ตรวจสอบความถูกต้องของสไตล์ชีต ทดสอบการตอบสนองของหน้าจอ และบริหารจัดการเวอร์ชันของโครงการอย่างเป็นระบบ

2.14 งานวิจัยที่เกี่ยวข้อง
ผู้จัดทำได้ศึกษาค้นคว้างานวิจัยและบทความวิชาการที่เกี่ยวข้องกับการพัฒนาระบบบริหารจัดการสินทรัพย์ การประยุกต์ใช้รหัสคิวอาร์ และการออกแบบส่วนต่อประสานผู้ใช้ เพื่อนำมาเป็นแนวทางในการดำเนินงาน ดังนี้
2.14.1 สมชายและคณะ ได้พัฒนาระบบบริหารจัดการครุภัณฑ์ออนไลน์สำหรับหน่วยงานทางการศึกษา โดยใช้สถาปัตยกรรมเว็บแอปพลิเคชันร่วมกับฐานข้อมูลเชิงสัมพันธ์ ผลการศึกษาพบว่าการพัฒนาระบบที่เปิดให้แต่ละแผนกสามารถตรวจสอบสถานะครุภัณฑ์ในความดูแลได้โดยตรง ช่วยลดขั้นตอนการประสานงานและลดระยะเวลาในการตรวจสอบข้อมูลลงได้มากกว่าร้อยละหกสิบ ซึ่งสอดคล้องกับแนวทางการออกแบบระบบในโครงงานนี้ที่มุ่งเน้นการกระจายสิทธิ์การตรวจสอบข้อมูลไปยังหน่วยงานผู้ใช้งานจริง
2.14.2 วิชัยและกิตติศักดิ์ ได้ศึกษาการประยุกต์ใช้เทคโนโลยีรหัสคิวอาร์ร่วมกับเว็บแอปพลิเคชันในการจัดการและตรวจนับสินทรัพย์ถาวร ผลการวิจัยชี้ให้เห็นว่าการสร้างป้ายรหัสคิวอาร์ประจำสินทรัพย์ช่วยให้เจ้าหน้าที่สามารถนำสมาร์ตโฟนมาใช้ในการสแกนตรวจสอบข้อมูลหน้างานได้อย่างแม่นยำ ลดความผิดพลาดจากการบันทึกข้อมูลด้วยมือได้อย่างมีนัยสำคัญ ผู้จัดทำจึงได้นำแนวคิดดังกล่าวมาออกแบบระบบสร้างรหัสคิวอาร์และระบบจัดพิมพ์ป้ายสติกเกอร์ขนาดมาตรฐานในโครงงานนี้
2.14.3 ปิยะวัฒน์และคณะ ได้ทำการวิจัยเกี่ยวกับการออกแบบส่วนต่อประสานผู้ใช้และประสบการณ์ผู้ใช้งานสำหรับระบบสารสนเทศองค์กรขนาดใหญ่ โดยเน้นการจัดวางเลย์เอาต์แบบตอบสนองและการใช้ระบบรูปแบบสีที่ถนอมสายตา ผลการประเมินพบว่าผู้ใช้งานมีความพึงพอใจต่อระบบที่มีความยืดหยุ่นในการแสดงผลบนหลากหลายอุปกรณ์ และการมีโหมดการแสดงผลแบบมืดช่วยลดความเมื่อยล้าของสายตาเมื่อต้องปฏิบัติงานกับข้อมูลปริมาณมากเป็นเวลานาน ซึ่งเป็นแนวทางที่ผู้จัดทำนำมาประยุกต์ใช้ในการพัฒนาส่วนต่อประสานของระบบนี้
2.14.4 ธีรภัทร ได้ศึกษาสถาปัตยกรรมเว็บแอปพลิเคชันแบบจำลองมุมมองและตัวควบคุมด้วยโหนดเจเอสและเอ็กซ์เพรสในการพัฒนาระบบงานที่มีการประมวลผลข้อมูลจำนวนมาก ผลการทดสอบพบว่าการใช้การเรนเดอร์ฝั่งเซิร์ฟเวอร์ร่วมกับเทมเพลตเอนจินช่วยให้ระบบสามารถแสดงผลข้อมูลตารางขนาดใหญ่ได้อย่างรวดเร็วและใช้หน่วยความจำฝั่งไคลเอนต์น้อยกว่า จึงเป็นหลักการสำคัญที่ผู้จัดทำเลือกใช้เป็นแกนหลักในการพัฒนาระบบบริหารจัดการสินทรัพย์ในโครงงานนี้
